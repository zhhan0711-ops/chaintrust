# Contributing

Contributions that improve evidence quality, test coverage, documentation, and failure handling are welcome.

1. Fork the repository and create a focused branch.
2. Keep findings evidence-backed and preserve the product boundary: ChainTrust does not replace a professional security audit.
3. Add or update tests for behavior changes.
4. Do not include secrets, real private keys, or confidential contract source.
5. Open a pull request describing the problem, implementation, and verification performed.

For rule changes, include a minimal Solidity fixture that demonstrates both the intended detection and an important non-detection case.
